# Mandatary — conditional Phase 1 Kanban proposal

## Authorization and ownership

This is a **proposal, not an executable queue**. Do not create dispatchable implementation cards or start coding until Step 0 exit criteria are met and Nico explicitly approves Phase 1. Use existing project/board `mandatary`; never recreate the completed workflow-validation task or the existing Step 0 cards.

All implementation cards below are assigned to **`coder`**. Each must hand off with native `kanban_request_review(reviewer="reviewer")`; `reviewer` independently inspects the exact commit, tests, security boundaries and deliverables before closure. A dependent task must wait for the predecessor's reviewed completion, not merely its code submission. Use project-managed worktrees and feature branches. GitHub operations use `/opt/data/integrations/github/bin/axiom-github gh` and existing git credentials. Draft PRs only; no merge, deployment or authentication integration changes. Preserve `HERMES_WRITE_SAFE_ROOT`; scratch files belong in `/opt/data/scratch/`.

References below: **R** = `roadmap.md`; **TD** = `technical-decisions.md`. All tasks inherit R shared release criteria. No task may resolve an open architectural conflict unilaterally. The baseline's explicit permitted implementation alternatives do not authorize a different stack.

## Requirement coverage and boundaries

- P1.01–04: supported stack, developer workflow, CI, embedded persistence and logging.
- P1.05–10, P1.16: local password policies, TOTP, WebAuthn, credential/recovery/session lifecycle, one policy administrator, users/groups/agents.
- P1.11–14, P1.17: endpoint-scoped container identity, per-operation authorization, self-protection, policy UI, API/MCP parity and strict catalog.
- P1.15: basic persistent counts; P1.18: backup/restore; P1.19–20: lightweight Compose product and every shared release gate.
- Phase 2 retains independent discovery, exec, access requests/temporary grants, SMTP/webhooks and statistics UI. Phase 3 retains Authentik/multiple administrators, own-session/login visibility and policy audit. Phase 4 retains operations UI/interactive TTY. Phase 5 retains multi-host transports. Schema/interface preparation is not permission to ship future features as stubs.

Keep every card approval-blocked until Nico authorizes dispatch. Do not create a second parallel reviewer card that lets implementation close before review.
