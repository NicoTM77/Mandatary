# P1.20.1 — Firefox recovery-code reveal fix and restrained Mandatary branding

Local contribution to the P1.20 release branch (reviewer finding R1 plus the approved logo/theme brief). Presentation
only: no authentication, authorization, API, routing or navigation change.

## A. R1 — Firefox `recovery-reveal-phone` (SH-9a / P1-E3)

**Symptom (reproduced at baseline `f306a2a`).** `TestSecurityUIBrowser/firefox/recovery-reveal-phone/{light,dark}` failed with
`replacement code: Hide the code button is below the fold after focus (... Hide the code button: top 852 ...)` at 390x844.

**Root cause (measured, not assumed).** On the public recovery page the one-time replacement-code card is the second block under
a tall pre-session chrome (theme-toggle row 60 px, then 24 px padding, a 36 px brand lockup and 24 px margin = 144 px before the
first alert). In Firefox, whose fallback system font is wider than the other two engines' on this host, the card is taller still;
the **Hide the code** button, which is disabled until the checkbox is ticked, ended at y = 896 against an 844 px viewport.
The scenario scrolls each control into view by calling `focus()`; a disabled button cannot take focus, so nothing scrolls and the
button stays below the fold. Chromium and WebKit passed on the same code, so the card fits their metrics (Firefox wraps more lines
in the fallback font used on this host); the disabled-button blind spot therefore only showed in Firefox. The test is
right: a person looking at a freshly revealed one-time code on a phone should see how to dismiss it without hunting. It was not
changed, relaxed or skipped, and the viewport was not enlarged.

**Fix (layout only; reveal/hide security, disabled/enabled behaviour, focus handling and keyboard access untouched).**

| Change | Where | Effect on phone |
|---|---|---|
| Pre-session frame: one 56 px top bar holds the brand (left) and the theme toggle (right); main content starts 16 px below it. The centred lockup above the card is gone. | `CenteredFrame` in `ui/AdminShell.tsx` | −72 px before the first block |
| Reveal card padding 20 → 16 px (≥ `sm`: unchanged 24 px); code box padding 16 → 12 px (≥ `sm`: unchanged); acknowledgement block margin/padding 20/16 → 16/12 px (≥ `sm`: unchanged) | `ui/SecretReveal.tsx` | −24 px inside the card |

Measured with the product's own scenario in Firefox (worst case on this host; the replacement-code card):

| Control | top / bottom before (y, px) | top / bottom after (y, px) |
|---|---|---|
| Reveal heading | 333 / 389 | 257 / 313 |
| Copy code | 714 / 758 | 630 / 674 |
| Acknowledgement checkbox | 797 / 817 | 705 / 725 |
| Hide the code (disabled) | **852 / 896** | **760 / 804** |

The button now ends 40 px inside the 844 px fold with the widest fallback font seen, instead of 52 px outside it.

## B. Brand assets and header integration

* `web/brand/` holds the approved artwork and `THEME.md` verbatim (SHA-256 in its README) plus a README. The full logos (icon, wordmark
  and tagline *Authority by design.*) are source assets only; the application shows the **icon plus the lowercase word `mandatary`,
  without the tagline**, built by `ui/BrandMark.tsx` (`BrandLockup`) from the icon's own path data (a vitest compares it with the files).
* Shared headers only: the sidebar/brand row of `AdminShell` (24 px glyph, 16 px bold wordmark, inside the existing 56/64 px row, so header
  height is unchanged) and the pre-session top bar of `CenteredFrame` (28 px glyph, 17 px wordmark; no sign-in redesign beyond moving the
  lockup into that bar). No hero, animation or marketing surface. The glyph and the word fit beside **Menu** / **Use … theme** at 390 and 360 px.
  In the pre-session bar only, below 350 px the word becomes visually hidden (still the accessible name) and the glyph stays, because the
  long theme-toggle label would otherwise leave about 12 px; the shell row has room down to 320 px and keeps the word.
* Colours are the `--brand-*` tokens (`style.css`), set per `data-theme` to the THEME.md values (dark: M and wordmark Ice `#F5F8FC`; light: Midnight
  `#101B2A`; gateway Mint `#5DE0C5` and pillars Periwinkle `#87A9FF` in both; the tagline colours are not used because the tagline is not shown).
  Rendered colours were read back from computed styles in all three engines.
* Inline SVG, not `<img>`: the CSP allows `img-src 'self'` only and the bundler would turn a small SVG into a blocked `data:` URI; inline
  elements also follow the page's theme tokens, so the mark cannot be the wrong theme relative to its surroundings.
* `ThemeProvider` now applies `data-theme` in a layout effect. Before, on a dark system the first committed render (including the brand
  mark) carried the light default for a moment (observed in Chromium, Firefox and WebKit: mark `rgb(16, 27, 42)` on `rgb(242, 245, 245)` with no
  `data-theme` at insertion); now it is already dark when the mark is inserted (`rgb(245, 248, 252)` on `rgb(11, 18, 19)`).
* Accessible name: the glyph is `aria-hidden`; the visible word is the only name, so a screen reader announces "mandatary" once. It is not a link or landmark.
* **Wordmark font.** Manrope (the approved wordmark face) is not installed on the build host and the CSP serves no web fonts, so the
  header wordmark is live text in the existing system font stack, bold with −0.03 em tracking to approximate the artwork. Exact Manrope
  would need an owner decision (ship the OFL font, or convert the wordmark to outlines); it is not introduced here.

### Theme adaptation (restrained)

Neutral surfaces, semantic colours (danger, warning, success) and the focus-ring thickness are unchanged. Only the **accent** family moved
toward the brand, with every pair re-verified in `theme-contrast.test.ts`:

| Token | Light before → after | Dark before → after |
|---|---|---|
| `--accent` / `--focus` | `#0b6e78` → `#00766a` (5.5:1 on white) | `#4fc3ce` → `#5de0c5` Mint (10.7:1 on surface) |
| `--accent-hover`, `--accent-text` | `#095a63` → `#005f55` | `#7ad6de` → `#8aebd7` |
| `--accent-soft` | `#dcf0f2` → `#d9f3ee` | `#123a3f` → `#10352f` |
| `--accent-fg` | `#ffffff` (unchanged) | `#041416` → `#04201b` |

Brand Mint on white is 1.6:1, so it is never used for light-theme text or controls; Periwinkle is identity-only. The brand colours are
identity, not status: info (accent) and success (green) are close in hue in the dark theme, so they remain distinguished by icon and
title text, never by colour alone (checked in screenshots).
