## What the gate changed

The gate ran the new `policy-flows` browser scenario on every engine and on the phone viewport, which the
contribution had run on desktop Chromium only. Two defects were in the test script, none in the product:

* **Phone viewport.** The last step waited for the primary-navigation link `Agent tokens`, which a 390 px shell
  collapses behind the `Menu` button, so it was never visible. The step now opens the menu first, like every
  other navigation step (`web/tests/security-ui-browser.mjs`).
* **Playwright WebKit and native `<select>`.** WebKit 27.2 reports the console error
  `Refused to apply a stylesheet because its hash, its nonce, or 'unsafe-inline' does not appear in the style-src
  directive` for any native `<select>` under the product CSP. The gate reproduced it on a bare page with no
  Mandatary code (WebKit: reported with a select, none without; Chromium 156 and Firefox 157: nothing either way),
  which is the C3 observation O3. The product CSP is unchanged and still asserted verbatim. The browser script
  now counts that one exact message apart, only on WebKit and only while the page really contains a `<select>`;
  any other console text, on any engine, still fails the run. The count is printed (`webkitSelectNotes`).
  Whether real Safari does the same is **unverified**.
